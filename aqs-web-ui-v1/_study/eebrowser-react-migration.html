EEBrowser.vbs → React Migration

A line-by-line analysis of the 1,235-line legacy VBScript browser controller, mapped to the React architecture already proven in the POC. Every mechanism, its React replacement, and why.

Task 5: Windows_Load and supporting functions
The core insight

EEBrowser.vbs is one file doing 8 distinct jobs (page init, server calls, event delegation, frame communication, data flags, XML data island, modal lifecycle, page-specific hooks). In React, each job is a separate, testable unit — a route loader, a Zustand store, a hook, or a config object. No single file replaces EEBrowser. The architecture replaces it.

1 Module-Level Flags → Zustand Stores Lines 1–113 replaced

EEBrowser keeps 20+ global variables (mblnPageLoaded, mblnCallServer, mblnEEDataChanged, mblnClosing, etc.) to coordinate timing between async operations and prevent race conditions. Every handler checks these flags before acting.

Legacy VBScript

Dim mblnCallServer      ' True = OK to call server
Dim mblnDoBrowserCommands
Dim mblnEEDataChanged   ' dirty flag
Dim mblnNavButtonClicked
Dim mblnClosing
Dim mobjAQSMain         ' parent frame ref
Dim mxmlDoc             ' XML Data Island

React (Zustand stores)
// appStore — global session state
const useAppStore = create((set) => ({
  isDirty: false,
  variables: {},
  setDirty: (d) => set({ isDirty: d }),

// pageStore — per-page control state
const usePageStore = create((set) => ({
  pageId: null,
  controls: {},
  loadPage: (pb, merged) => set(...),

Why this is better: Each flag becomes a typed property in its own store. React's reactivity means components automatically re-render when state changes — no manual flag-checking in every handler. The mblnPageLoaded guard is completely unnecessary because React doesn't render until data arrives (the route loader ensures this).

EEBrowser has 20+ global flags to prevent race conditions. In React, the component lifecycle handles that automatically — you can't interact with a page until it renders, and it doesn't render until the data is loaded. So all those mblnPageLoaded checks just disappear.

3 Event Delegation → React Event Props Lines 404–446, 912–987 simplified

Nearly every VBS event handler follows an identical pattern: check mblnPageLoaded, check mobjAQSMain Is Not Nothing, then delegate to the parent frame's handler. This exists because VBScript has no module system — the content frame has to reach up to the parent for any behavior.

Legacy pattern (repeated 15+ times)

    If Not mobjAQSMain Is Nothing Then
      Call mobjAQSMain.OnFocusHandler(strID, Window)
    End If
  End If

React — events are local
// FieldRenderer — each field handles its own events
function FieldRenderer({ control }) {
  const handleChange = (value) => {
    usePageStore.getState().setValue(
      control.matchcode, value
    );
    // If the field has a server action, fire it
    if (control.hasAction) {
      executeAction({
        session, matchcode: control.matchcode,
        action: 'change', value,
      }, navigate);
    }
  };
  return <TextField onChange={handleChange} />;
}

Why the delegation pattern disappears: In the frame architecture, the content page can't do anything alone — it has to call up to mobjAQSMain for every action. React is a single-page app with no frames. The component that renders the control IS the handler. The 15 nearly-identical delegation stubs (OnFocusHandler, ButtonOnClickHandler, CalendarButtonOnClick, InfoButtonOnClick, NoteButtonOnClick, ListButtonOnClick, ListButtonClick, OnTabClickHandler, DateOnFocusHandler, DateOnKeyUpHandler) all collapse into React's native event system.

The legacy code has 15 event handlers that all do the same thing — check two flags, then delegate to the parent frame. That's a workaround for the frame architecture. In a React SPA, there are no frames, so the component handles its own events directly. Fifteen repetitive handlers become standard React onChange / onClick props — each written once on the field that needs it.

5 XML Conversion Utilities → Eliminated Lines 525–651 eliminated

127 lines of functions to convert between VBScript arrays and XML strings: convertArrayToXML, convertXMLToArray, convertBrowserXMLTo2DArray, EscapeForHTTPTrip, UnEscapeFromHTTPTrip. These exist because the server speaks XML and VBScript arrays aren't serializable.

6 CallServer → api.pageLayout() + dispatchCommands() Lines 654–857 replaced

The core of EEBrowser: 203 lines that package the 13-slot marrEEData array + session info + server call XML into an XML payload, POST it synchronously to xmlservercall.asp, parse the response XML back into arrays, and execute browser commands. This is the single communication channel between page and server.

What changed architecturally:

  • Sync → Async: The VBS call freezes the browser. React uses async/await — the UI stays responsive.
  • XML → JSON: No convertArrayToXML / convertXMLToArray round-trip.
  • 13-slot array → typed object: marrEEData(0..12) becomes { matchcode, action, value, formData } — self-documenting.
  • Monolithic → split: CallServer = package + send + parse + execute. React splits this: api.pageLayout() sends/receives, dispatchCommands() executes.
CallServer is the heart of EEBrowser — 203 lines that build XML, POST it synchronously (freezing the browser), parse the response XML, and execute commands. In React, this becomes two clean functions: api.pageLayout() sends JSON and gets JSON back asynchronously, and dispatchCommands() routes each command to the right place. The 13-slot marrEEData array becomes a typed object with named properties. The browser never freezes.

8 Window_OnBeforeUnload → useBlocker + beforeunload Lines 1084–1133 replaced

Handles unsaved data: if the page is a modal with changed data and the user didn't click a nav button, it fires a CANCEL CallServer to roll back server state, then nullifies all frame references to prevent memory leaks in IE.

Legacy — manual cleanup
Sub Window_OnBeforeUnload()
  If document.all("hddIsModal").Value = "1" Then
    If mblnEEDataChanged Then
      If Not mblnNavButtonClicked Then
        marrEEData(1) = "CANCEL"
        Call CallServer()
      End If
    End If
  End If
  Set mobjAQSMain = Nothing
  Set mobjMenuFrame = Nothing
  Set mobjTreeFrame = Nothing

    "local_before_window_unload")
End Sub
React — Router blocker + effect cleanup
function LobPage() {
  const isDirty = useAppStore(s => s.isDirty);

  // Block in-app navigation if dirty
  const blocker = useBlocker(isDirty);

  // Block browser close/refresh if dirty
  useEffect(() => {
    const handler = (e) => {
      if (isDirty) e.preventDefault();
    };
    window.addEventListener('beforeunload', handler);
    return () => window.removeEventListener(
      'beforeunload', handler
    );
  }, [isDirty]);

  // Cleanup on unmount
  useEffect(() => {
    return () => useAppStore.getState().reset();
  }, []);
}

Key differences: No manual frame reference cleanup (no frames exist). The CANCEL CallServer for rollback moves to the blocker confirmation handler — if the user confirms leaving, fire the cancel API call. React's useEffect cleanup function replaces Set obj = Nothing for memory management.

The legacy Window_OnBeforeUnload does two things: sends a CANCEL to the server to roll back if data changed, and manually nullifies frame references to prevent IE memory leaks. In React, useBlocker from React Router handles the "are you sure?" prompt for in-app navigation, and the standard beforeunload event handles browser close. Memory management is automatic — React cleans up when a component unmounts.

11 Frame Communication → Eliminated by SPA Lines 145–157 + throughout eliminated

EEBrowser runs in the content frame of a frameset. It communicates upward to mobjAQSMain (the main frame, AQSMain.asp) for every operation — menu updates, tree selection, navigation, browser commands. The parent frame references (mobjAQSMain, mobjMenuFrame, mobjTreeFrame) are established in window_onload and used everywhere.

In React: There is no frameset. The entire application is a single page. What was the "main frame" is now the AppLayout shell component (sidebar, header, breadcrumbs). What was the "content frame" is now a React Router Outlet. Communication between "frames" is just Zustand store reads — the sidebar reads appStore.currentLob, the header reads appStore.pageTitle. No cross-frame scripting, no parent.frames("menu"), no Set mobjAQSMain = Nothing cleanup.

The whole frame architecture — mobjAQSMain, mobjMenuFrame, mobjTreeFrame, all the cross-frame calls — is eliminated. React is a single-page app. The sidebar, header, and content area are all components in the same page that share state through Zustand stores. No frames, no cross-frame communication, no reference cleanup. The 15 delegation handlers that call mobjAQSMain.SomeHandler() are just gone.
12 ReDimBrowserArray / ShowUserMessage → Native JS / MUI Lines 1210–1231 eliminated

ReDimBrowserArray resizes VBScript arrays (marrServerCalls, marrListItems) because VBScript arrays are fixed-size. ShowUserMessage wraps a UserMessage ActiveX object to display dialogs.

In React: JavaScript arrays grow dynamically — .push() just works, no ReDim needed. User messages display via the browserCommandStore notification system, rendered as MUI Snackbar/Alert components. No ActiveX, no modal blocking dialogs.

ReDimBrowserArray exists because VBScript arrays are fixed-size — JavaScript arrays grow automatically. ShowUserMessage uses an ActiveX control for dialogs — React uses MUI Snackbar notifications, non-blocking and accessible. Both functions are simply unnecessary in a modern stack.

Architecture: before and after

How the data flows in legacy vs. React

Legacy flow (EEBrowser.vbs)

Page loads in content frame
  → window_onload() fires
    → get parent frame references (mobjAQSMain)
    → load XML Data Island (MSXML2.DOMDocument)
    → set 20+ module flags
    → focus first control, set mblnPageLoaded = True

User changes a control
  → OnFocusHandler → mobjAQSMain.OnFocusHandler (delegate UP)
  → ButtonOnClickHandler → mobjAQSMain.ButtonOnClickHandler
  → OnCheckBoxClick → fill marrEEData slots → CallServer()
    → convertArrayToXML (3 arrays)
    → synchronous XMLHTTP POST to xmlservercall.asp
    → parse response XML → convertXMLToArray
    → mobjAQSMain.ExecuteBrowserCommands()
      → SET_VISIBLE, SET_DISABLED, DISPLAY_MESSAGE, etc.

User leaves page
  → Window_OnBeforeUnload
    → if dirty + modal + not nav-clicked: CANCEL CallServer
    → nullify frame references
    → PageUniqueRoutine("local_before_window_unload")

React flow (POC architecture)

Route changes
  → lobPageLoader() runs BEFORE render
    → api.navigate(session, pageId)        // Navigation API
    → api.pageBuild(session, nav.pageId)   // PageBuild API
    → return { pageBuild, pageConfig }

Component renders with data ready
  → useEffect → pageStore.loadPage(pageBuild)
  → dispatchCommands(pageBuild.commands)   // initial commands
  → FormRenderer renders all controls from pageStore

User changes a control
  → onChange → pageStore.setValue(matchcode, value)
  → if hasAction: executeAction(session, matchcode, value)
    → api.pageLayout(session, req)         // JSON POST, async
    → dispatchCommands(result.commands)
      → SET_VISIBLE → pageStore.applyCommands()
      → DISPLAY_WARNING → browserCommandStore.notify()
      → NAVIGATE → router.navigate()

User leaves page
  → useBlocker(isDirty) shows confirmation
  → useEffect cleanup → appStore.reset()
  → pageConfig?.onBeforeUnload?.()        // LOB hook
