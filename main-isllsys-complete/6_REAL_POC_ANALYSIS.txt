SECTION 2: ARCHITECTURE DEEP DIVE
================================================================================

2.1  DATA FLOW: SERVER CALL LIFECYCLE
-------------------------------------

  User Action (blur/change/click)
       |
       v
  field-renderer.tsx (handleBlur/handleChange/handleClick)
       |
       v
  payload.ts (handlerForEEData) -- builds EEData object
       |
       v
  page-data.ts (pageData service) -- POST /ui/page/data
       |
       v
  Server Response: { sessionInformation, eeData, listItems, browserCtl }
       |
       v
  session-store.ts (updateSessionFromArray) -- updates session
       |
       v
  commands.ts (handlerForBrowserCommands) -- processes browserCtl.call[]
       |
       v
  25+ verb handlers: NAVIGATE, SET_TEXT, SET_VALUE, SET_ATTRIBUTE,
  SET_DISABLED, SET_READONLY, SET_REQUIRED, SET_FOCUS, SET_VARIABLE,
  LOAD_COMBO, ADD_LISTITEM, CLEAR_COMBO, OPEN_MODAL, CLOSE_MODAL,
  DISPLAY_ERROR, DISPLAY_QUESTION, DISPLAY_INFORMATION, DISPLAY_MESSAGE,
  BUSINESS_ERROR, CALL_SERVER, REFRESH_TREE, REFRESH_MENU,
  CLEAR_ACTIONMENU, CLEAR_SESSIONXML_ITEM, LOAD_GRID, CLEAR_GRID,
  NAVIGATE_CYCLING


2.2  NAVIGATION LIFECYCLE
--------------------------

  Tree click / Menu click / Button click
       |
       v
  page-navigation.ts (pageNavigation service) -- POST /ui/page/navigation
       |
       v
  Response: { nodeKey, action, url, xmlFile, frame, modal*, xmlDetail, ... }
       |
       v
  Session store update (updateSessionFromResponse)
       |
       v
  Frame routing:
    - frame="MAIN"      -> React Router navigate to /static/{folder}/{file}
    - frame="MODAL"     -> ModalStoreApi.open() -> modal.tsx loader
    - frame="NEWWINDOW" -> window.open()


2.3  MODAL LIFECYCLE
--------------------

  onOpenModal(action, nodeKey, height, width)
       |
       v
  ModalStoreApi.open({ action, nodeKey, width, height })
       |
       v
  NavigationStoreApi.setDeferred(true) -- blocks main-frame navigation
       |
       v
  modal.tsx: clientModalLoader fires
       -> pageNavigation(action, nodeKey) -- gets XML/layout info
       -> pageLayout(xmlFile)            -- gets controls/buttons
       -> Returns: { controls, buttons, title, xmlFile }
       |
       v
  Modal renders form fields from controls
       |
       v
  User edits + clicks OK/Submit
       -> clientModalAction fires
       -> pageData(ZENTEDTCTL, eeData) -- commits changes
       -> Processes returned browser commands
       -> extractReturnValue(commands) -- captures SET_VARIABLE returns
       |
       v
  ModalStoreApi.close()
       -> NavigationStoreApi.setDeferred(false)
       -> use-deferred-navigation.ts replays nextAction


2.4  HANDLER AUTO-DISCOVERY
----------------------------

  import.meta.glob('/src/handlers/**/*.ts')
       |
       v
  Merge: common handlers (shared.ts) + page-specific overrides
       |
       v
  Example: pol-piphpol-20150801.ts overrides closeModal, adds
           logEffectiveDateChange, openStartOptionsModal
       |
       v
  Registered on window.frameHandlerRegistry via useRegisterHandlers


2.5  STORE ARCHITECTURE (10 Zustand Stores)
--------------------------------------------

  Store                    | Concern                  | Key Actions
  -------------------------|--------------------------|---------------------------
  auth-store               | Authentication           | setUser, clearUser, hydrate
  session-store            | Session state + xmlDetail | updateSessionFromArray,
                           |                          | setXmlDetailItem, toPayload
  global-vars-store        | UNIFIED: domain flags,   | setPolicyRated, setOptions,
                           | combo options, focus,     | requestFocus, setCommands
                           | browser-cmd execution    | Enabled, setExecuting
  navigation-store         | Nav lifecycle, deferred   | setDeferred, setNextAction,
                           | nav, cycling depth       | incrementDepth, markFrame
  modal-store              | Modal state + alerts      | open, close, setReturnValue
  tree-store               | Policy tree CRUD          | loadTree, addNode, selectNode
  menu-store               | Menu items                | setMenus (syncs nav store)
  grid-store               | Grid rows by matchcode    | setRows, clearRows
  loading-store            | Reference-counted busy    | begin, end, reset
  runtime-override-store   | Per-field overrides        | setOverride (disabled etc.)


2.6  FIELD REGISTRY & EE METADATA
-----------------------------------

  Registry Key  | Component    | EE Trigger | Trigger Event
  --------------|--------------|------------|---------------
  textbox       | Text         | Yes        | onBlur
  numeric       | Text         | Yes        | onBlur
  textarea      | Textarea     | Yes        | onBlur
  date          | DateField    | Yes        | onBlur
  combo         | Select       | Yes        | onChange
  radiobutton   | Radio        | Yes        | onChange
  checkbox      | Checkbox     | Yes        | onChange
  button        | ActionButton | No         | --
  xmllist       | DataGrid     | No         | --


2.7  JSON SCHEMA SYSTEM
------------------------

  Schema files define page layouts declaratively:
  - Layout type: flat | tabbed | form+grid | grid | nested-tabs
  - Controls: matchcode, controltype, ctrlabel, visible, disabled, required
  - Events: onClick bindings with handler references
  - Tabs: nested tab groups with control assignments
  - Grids: xmllist columns with header/width/matchcode

  Example: pol-piphpol-20150801.json (271 lines)
  - 5 tabs: Policy, Policy Detail, Billing/Misc, Insured Detail, Agent Detail
  - 19 controls on Policy tab (textbox, combo, checkbox, radiobutton, numeric)
  - xmllist on Insured Detail tab with 6 grid columns
  - Footer: Start Options, OK, Cancel buttons with onClick handlers


2.8  ROUTE CONFIGURATION
--------------------------

  /                     -> Root (Header + Outlet + Footer)
  /login                -> Login page (no auth middleware)
  /logout               -> Logout action
  /frame                -> Frame layout (with menu, tree, modal children)
    /menu               -> Menu resource route (clientMenuAction)
    /tree               -> Tree resource route (clientTreeAction)
    /modal              -> Modal resource route (clientModalLoader/Action)
    /static/:folder/:file -> StaticRenderer (clientStaticLoader)
    /dynamic/:folder/:file -> DynamicRenderer (clientDynamicLoader)
