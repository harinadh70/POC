VBS LINES ~224-280: ShowNextOnEdit TWO-ARM LOGIC
================================================================================

    ARM 1 (ShowNextOnEdit = "T"):
        EDIT/RLVUPDATE/EDITTYPRAT → DISABLE dtaNEXT

    ARM 2 (ShowNextOnEdit = "F"):
        EDIT/RLVUPDATE/EDITTYPRAT → HIDE dtaNEXT (SET_VISIBLE = "F")

    Both arms check session XML for "rlvupdateadd" and "chgtypratadd"
    to determine if it's a re-add during RLVUPDATE/EDITTYPRAT.

STATUS: *** GAP ***
POC FILES: command.ts handles SET_VISIBLE/SET_ENABLED verbs.
           runtime-override-store.ts tracks per-control overrides.
           BUT: No code reads ShowNextOnEdit from schema and applies
           the two-arm logic during page init.

WHAT TO BUILD:
    A shared handler utility (in handlers/common/shared.ts):

    function applyNextButtonRules(schema, action, sessionStore) {
        const showNextOnEdit = schema.pageHeader?.showNextOnEdit;
        const isReAdd = (action) => {
            if (action === 'RLVUPDATE')
                return sessionStore.getXmlDetailItem('rlvupdateadd') === 'yes';
            if (action === 'EDITTYPRAT')
                return sessionStore.getXmlDetailItem('chgtypratadd') === 'yes';
            return false;
        };
        const shouldRestrict =
            action === 'EDIT' ||
            ((action === 'RLVUPDATE' || action === 'EDITTYPRAT') && !isReAdd(action));

        if (shouldRestrict) {
            if (showNextOnEdit) {
                RuntimeOverrideStoreApi...setEnabled('dtaNEXT', false);
            } else {
                RuntimeOverrideStoreApi...setVisible('dtaNEXT', false);
            }
        }
    }

    Call from static-renderer/dynamic-renderer onMount.

EFFORT: Medium (30-40 lines)
NOTE: The 9/25/00 "TW" comment in the VBS says this should be server-driven.
      Long term, the PageLayout API should send the right commands.
